Requirements R14/R24/R25/R30–R37, §§12.1–12.8; consumers WX-20/26/39/40/41/43/44 and integration WX-33. This is design collateral, not an application implementation or evidence of a deployed Weather UI.

## Architecture and why

**Owner-approved revision:** Jason explicitly agreed to refactor the design against React + TypeScript after reviewing the framework recommendation. This supersedes the earlier Astro selection. Requirements §12.1's framework examples remain candidate context; product scope, routes, privacy and no-JavaScript reading requirements are unchanged.

Select React + TypeScript with React Router Framework Mode and its Vite build integration, server-rendered public initial pages and client-side navigation. Keep the same-origin Python API and separate asynchronous media/analysis workers. The web runtime is a thin Node rendering layer: it reads bounded public API projections, not the database, cameras, model service or object bucket directly. Basic archive links, video detail, timestamps, descriptions and download links remain usable without JavaScript. Observations and new videos update projections without rebuilding the site/archive.

The decisive requirement is coordinated interactive state: video playhead, source-time cursor, keogram/events and weather charts; URL-bound search/comparison filters; and an editor that preserves drafts across revision conflicts. A shared React component tree and route lifecycle provide one place to coordinate them. Astro could implement these features, but a growing collection of state-sharing islands adds an unnecessary composition boundary here. Next.js and SvelteKit remain capable alternatives; this project selects React Router's explicit route/data/rendering model while retaining Python's existing domain and worker boundaries. No second JavaScript backend owns weather truth or authorization.

[React Router Framework Mode](https://reactrouter.com/start/modes) supports typed route modules, code splitting and SSR/client rendering; its [rendering contract](https://reactrouter.com/start/framework/rendering) supports the chosen initial HTML plus hydration architecture. These primary docs were checked 2026-10-23; actual compatible package/server-adapter/image pins and deployed behavior remain to be qualified through D01. No React Server Components, experimental routing features, offline persistence or PWA requirement is introduced. Weather remains independent of WordPress.

### Component and data ownership

| State or responsibility | Selected owner and contract |
|---|---|
| Route and shareable filters | React Router URL parameters: date/camera/segment, units, validated measured filters and deliberate seek links. Parse through shared typed API contracts; browser back/forward reconstructs the same view. Never put session tokens, private notes or credentials in URLs. |
| Initial public page data | Route loaders fetch bounded same-origin API projections with cancellation/deadlines. SSR and client navigation use the same schema and revision semantics. Node uses only its fixed allowlisted API upstream, never visitor-selected fetch URLs. |
| Live current/history data | TanStack Query manages polling/request coordination for explicitly assigned current/history projections. Loader data seeds that same query identity; do not create an independently refreshing router copy of the same resource. Keys bind route filters, resolution, units and relevant revision identities. |
| Search results | Route submission/fetcher state owns one bounded search request and its displayed response. D12's no-result-cache policy applies: no persistent Query cache, speculative prefetch or automatic retries that repeat model work. Abort obsolete requests and ignore late responses for old filters; retain explicit unavailable/degraded semantics. |
| Player/chart interaction | One route-local React controller owns the selected media revision, authoritative time map and source-UTC cursor. Native HTML video reports playback; chart/keogram/event selection requests validated seeks through that controller. Transient pointer/playhead state stays out of server-data caches and does not trigger a fetch per frame. |
| Editor draft | Route-local memory owns draft, expected revision, dirty/conflict state and deliberate submission. Python owns authentication, authorization, CSRF, CAS, audit and publication. No optimistic public update before the committed server response. |
| Styling and transport types | CSS variables and CSS Modules use the selected theme/accessibility tokens. Generate TypeScript transport types from the committed API schemas and validate untrusted responses at the boundary; do not recreate a divergent handwritten weather model or trust compile-time types as runtime validation. |

Use shared accessible components for metric freshness, camera/product status, evidence/provenance, source interval, coverage and error states. Lazy-load chart/player/editor modules by route; do not ship private editor data or a full chart library to the small embed. Exact chart/control packages remain a bounded selection based on required zoom/cursor/gaps/keyboard behavior and license review, not an implicit adoption of a component suite. Basic video playback uses native HTML video; custom React controls must preserve browser/mobile and keyboard behavior.

### Hydration, cache and request discipline

Server requests have isolated state; no process-global QueryClient, operator cache or mutable loader data can cross users. Serialize only approved public projection fields using safe framework serialization; never embed private configuration, credentials, raw receipts or editor state in HTML/hydration/public source maps. The [TanStack SSR guide](https://tanstack.com/query/latest/docs/framework/react/guides/ssr) describes request-local query state and hydration; its [defaults](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults) require explicit overrides for Weather's polling/retry policy. Framework capability is not proof of isolation.

Current conditions use one in-flight request and approximately 15-second foreground refresh, pause when hidden and bounded backoff. Disable automatic retry bursts and additional focus/reconnect polling that would duplicate the selected schedule; cancellation and effect cleanup must also work under React development double mounting. Polling/error recovery never resets observed_at, received_at or per-metric valid_until. Seed server time and timezone explicitly so hydration agrees on stale/missing states and repeated DST-hour labels; later age updates use the source timestamps, not hydration time.

An in-memory last-known public value can remain visible with its original time and an unavailable/stale label. It is not authorization to reuse withdrawn descriptions, previews, private data or invalidated measurements as current. Revalidate revision/visibility on navigation and refresh; discard affected local entries on authoritative invalidation. Bytes already delivered cannot be recalled. Do not persist API state in localStorage, IndexedDB or a service worker. Public page caching follows D14/D16; search/private responses are no-store. Server-rendered fallbacks preserve meaningful status and accessible text when API or hydration fails.

### Authentication and deployment boundaries

Keep login/callback/session/CSRF enforcement and private API routes in Python under the existing operator identity design. The Node web server receives no DB, camera, model, Garage or OIDC client-secret authority. The editor initially renders an unprivileged shell, then obtains private data through authenticated same-origin API calls; do not serialize private API data into public SSR hydration. A visual route guard is not authorization. Avoid a second Node session system or broad cookie-forwarding proxy. Private form saves carry the server-issued CSRF token and expected revision; automatic retries on mutations are disabled. Logout/revocation clears private query state while preserving only the operator's unsaved in-memory draft for deliberate recovery, never automatic resubmission or cross-identity reuse.

The E12 web image now packages the React Router Node server and versioned static assets; API/media image responsibilities are unchanged. D01/WX-02 must pin React/React DOM, Router build/runtime adapter, Vite, TypeScript and TanStack Query in a complete lockfile, verify Node compatibility, reproduce the build and qualify the artifact offline. HTML, route manifests and hashed assets must be deployed compatibly; an old open tab during rollout needs a controlled reload path, never missing-chunk loops. WX-34 records app/API schema compatibility and rollback coordinates. No public package/CDN downloads occur at runtime.

### React-specific acceptance

WX-20/26/39/43/44 and integrated WX-33 must demonstrate direct deep links, server-rendered no-JavaScript reading/navigation, hydration without private leakage or stale-state mismatch, route-level errors and keyboard focus/scroll restoration. Cover back/forward filter restoration, rapid route/query changes with late responses, duplicate-effect/poll prevention, unmount cleanup, one active video, source-time cursor/seek agreement and preservation of playhead where a rendition switch permits it. Test stale editor CAS, expired identity, failed save and navigation-away draft protection without silent overwrite. Verify request-local isolation across simultaneous SSR requests and shared-cache exclusion for search/private responses. Test a rolling web/API deployment with an already-open tab, unavailable JS/API, narrow/zoomed layouts and the required mobile/browser matrix. Passing framework build or schema checks alone closes none of those behaviors.

Use ink text on mint, not white text. Border color alone must not identify an essential input boundary or chart series.

Calculated solid-color contrast on white: ink 16.191, muted 5.407, forest 8.196, leaf 4.995, fault 6.536, gold 2.188 and mint 1.562. Therefore the requirements' candidate gold focus token is **not** the sole focus indicator: use a two-pixel forest outline with a two-pixel contrasting white separation, and inspect it against every actual surrounding surface. Links use underlines where prose would otherwise rely on color. Chart lines use labels/patterns and missing-value gaps, not only color. These calculations are not full accessibility or rendered-state acceptance.

Use an 80-rem maximum shell, 1-rem minimum mobile gutters, restrained 0.375/0.625-rem radii and 44-pixel minimum target boxes. Main text starts at 1rem with comfortable line height. Intended local fonts are the observed IBM Plex Sans Variable and IBM Plex Mono; system sans/mono remain immediate fallbacks. No font bytes have been copied into Weather. The [exact font review](font-reuse-review.md) identifies both Fontsource 5.3.0 packages by verified archive integrity and byte-identical selected members, reviews OFL-1.1 notices and selects unmodified local distribution with those notices. Actual artifact inclusion remains implementation work. Do not copy unrelated theme templates, private content or the entire WordPress stylesheet. Use text “Weather” with a clear vallery.net backlink initially; a copied wordmark needs its own provenance.

## Responsive composition contract

These are wireframe specifications to render and inspect in the implementation collateral; they are not completed visual wireframes. Test 320, 390, 768 and 1440 CSS-pixel viewports, 200% zoom, long content and keyboard operation.

| Surface | Wide layout and reading order | Narrow layout and essential states |
|---|---|---|
| Global shell | Weather/backlink, Today · Archive · Weather history · Search · About, page heading, main content, provenance/help footer. | Wrap navigation or expose an accessible labeled menu; do not force horizontal page scrolling. Skip link and current-page indication persist. |
| Today | Timestamped station conditions first; per-metric freshness; three equal camera cards with delayed preview, cycle status, latest poster/video and keogram; recent events below. | Stack east, west, front yard; keep camera labels and source age adjacent to images. Distinguish embargoed/absent/stale preview from loading. Start no video automatically. |
| Archive/day | URL-bound date/camera/segment/status filters; three-camera grid containing daytime and overnight; exact solar bounds and coverage. | Reachable date controls before cards; overnight explicitly shows both dates. Link calendar-day hourly stills separately from solar-cycle products. |
| Player | Full panorama above linked plots; source-time cursor, quality selector/download, keogram/events, narrative and measured evidence below. | Stack plots without cropping panorama. Text equivalents remain readable without playback. Preserve playhead on quality changes when possible; one active player. |
| Stills | Calendar date/hour/offset controls, camera comparison, selection timestamp/coverage and derivative provenance. | Preserve repeated DST-hour offsets and missing/expired slots. Never link a private original or call an absent slot loading forever. |
| History/almanac/events | Range/resolution/units and coverage before plots; observed-history records; paginated events with measured/visual/manual basis. | Summary/table alternative and bounded exports; no zero substitution for unknowns or implied complete historical records. |
| Search | Query plus typed filters, visible semantic/fallback state, current-revision results with bounded evidence intervals. | Filters and results preserve back/forward URLs; empty results differ from unavailable search. Seek labels state actual precision. |
| Private editor | Current public revision beside automated proposal and human override; evidence changes/conflicts visible; explicit save reason and revision. | Linear readable order; never expose private notes/favorites through public controls. CAS conflict preserves draft for deliberate rebase, not silent overwrite. |
| Embed | Compact measured values, observation times/stale state and link to full Weather. | Fit narrow parent containers; no privileged cookies or parent DOM access; keyboard and reduced-motion support. |

All product cards use explicit capturing, queued, processing, published, partial, unavailable or expired labels where appropriate; analysis execution state remains separately labeled. Useful state changes are announced once; 15-second refreshes do not repeatedly read all values to screen readers. Visible views poll current conditions at approximately 15 seconds with one in-flight request, bounded backoff and pause when hidden. Display source timestamps/age even when an HTTP response or cache is fresh. Polling does not refresh the source measurement itself.

## Private identity and mutation boundary

Use fleet identity with an application-verified authenticated subject and explicit Weather operator authorization. Never grant operator access merely because a user is authenticated, has a LAN address, or arrived through a hidden route. The [operator identity design](operator-identity-design.md) now selects server-side OIDC code with PKCE, an explicit issuer/subject operator allowlist and opaque short-lived sessions based on an existing estate client pattern. Actual provider/client enrollment, Python library pin and provider-side revocation still require owner qualification. Do not trust browser-supplied identity headers or borrow WordPress sessions by assumption.

The private API checks authorization on every private read and mutation, uses its separate least-privilege database role, and records actor/reason/revision/evidence bindings. Cookie-based sessions require Secure/HttpOnly scoped cookies and CSRF defenses; use same-origin request validation and a session-bound token for mutations. Session expiration/revocation rejects writes without discarding the operator's visible draft. Public readers never receive privileged cookies, raw diagnostics, unpublished claims, private originals, favorites or operator notes. Private responses are not shared-cache content. CAS rejects stale revisions and the existing editorial/outbox contract governs atomic publication/search withdrawal; frontend optimism never bypasses it.

Identity tests must cover anonymous access, authenticated nonoperators, forged headers, revoked membership/session, CSRF, stale CAS, parallel human/automated changes and restored revision state. No new identity, credential, role or access policy is created by this planning decision.

## Embed and frontend security

Implement `/embed/weather/` in Weather and link the parent change to [OWN-EMBED](https://github.com/VerdifyConsultancy/wordpress/issues/242). Proposed initial parent origin is exactly `https://vallery.net`; additional origins such as www require observed need and explicit policy configuration, not a wildcard. Emit a narrow CSP frame-ancestors list only for the embed response; normal and private routes deny framing. This is framing permission, not API CORS or operator authorization. Do not depend on third-party cookies or send privileged state through postMessage. The parent controls its placement; Weather owns the card's contract and polling.

Self-host scripts, icons, fonts and player assets. Render narrative/editorial values as escaped text unless a deliberately restricted sanitizer contract is separately defined; do not inject model HTML. Build a restrictive CSP from actual generated assets, with no broad unsafe-inline exception to silence errors. Do not embed private runtime configuration, stack traces or internal endpoints in error pages, hydration data or public source maps. Validate allowed/denied parent origins in real browsers along with the specified Safari/iOS, Android/Chrome and desktop coverage; source headers alone are not framing acceptance.
