# Implementation decision register

Status: research in progress, 2026-10-23. This register selects working designs and exposes the evidence still needed. It does not replace the required individual D01–D16 ADRs or qualify production. [WX-00](https://github.com/jvallery/weather/issues/1) tracks completion. Accepted product choices remain authoritative.

## Evidence discipline

`E01` is the private, timestamped fleet baseline collected during this audit. It records source revisions separately from live Argo revisions, database topology and selected non-secret storage configuration. It establishes existing platform surfaces, not Weather enrollment, resource admission, durability or performance. Its raw receipt is kept outside this public repository. Additional evidence must identify its observation time, exact source/build and what it actually proves.

`S01`–`S50` refer to the primary-source ledger in the requirements. Each individual ADR must revalidate the references relevant to its choice. Historical review claims are not fresh runtime evidence.

## Framework tradeoff

Astro plus a Python API is the working choice because the archive, about pages and shareable video routes benefit from server/static HTML while charts and live conditions need bounded interactive islands. Python can share timing, astronomy, telemetry, schema validation and worker contracts. The alternative is an integrated web framework with a separate media worker; it reduces frontend/API deployment units but does not eliminate worker, object-gateway or security boundaries. The final ADR must confirm existing build support and pin versions before treating this selection as closed.

## Resource and availability constraints

No Weather workload is admitted yet. Current scheduler and working-set samples show uneven worker headroom and substantial limit overcommit; cluster totals alone are not a placement decision. Preserve cordoned control-plane nodes, the protected camera-worker taint, resident model allocations and reserved N-1 recovery capacity. All throughput/quality experiments need an existing supported containerized job path, finite resource/deadline limits and retained receipts. The Mac remains an editing/orchestration surface.

Database/API replica availability is separate from NAS-backed capture and uncached media availability. An inference outage must not stop measurements or publication. A NAS outage may stop durable capture and object access; a healthy metadata endpoint cannot conceal those failures. Operational targets cannot erase these failure domains.

## Research versus implementation gates

A selected design may carry mandatory isolated implementation tests without claiming they already passed. An unresolved material approach (currently including the UDP attachment, full offsite custody disposition and public video transport) is still a research blocker. Do not close WX-00 or start application implementation until the full planning pass is complete. Continue independent evidence collection, contract writing and issue refinement while blocked decisions are resolved.
