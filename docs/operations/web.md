# Public web application

The Weather Node server uses React Router 8.5.0 SSR and an explicit Express entrypoint. Every public
page is readable without JavaScript; enhanced navigation, current-condition polling, chart interaction
and quality selection use the locally bundled client code. There is no PWA, external asset fetch or
persistent browser cache for weather data.

The read-only server consumes only the fixed `API_ORIGIN=http://api` Service on port 80. It forwards no
cookies or authorization headers, follows no redirects, allows only the listed public API paths, and
bounds each request to 6 seconds and 4 MiB. At most sixteen upstream requests run at once: four per
document, because Today reads current conditions, the metric registry, recent events and the latest
catalog entries concurrently, and a video page reads its catalog entry, the registry and one or two
event days. API-backed
document/data responses have four slots and a 15-second absolute deadline, matching the initial
512 MiB web memory limit. Static files, process health, the loader-less About and Search pages and the
lazy route manifest (`/__manifest`) do not consume those slots. Overload is reported as "Weather is
busy" with `503` and `Retry-After: 5`, never as "API unavailable": a document request gets that text, and
a hydrated client navigation's `.data` request gets the body `busy`, which the root error boundary
renders as the same busy state. Failures render
sanitized unavailable states. The process has no database, camera, object-store or model credential.

HTTP is on `PORT` (3000); metrics use a separate `METRICS_PORT` (9000). `/healthz` and `/readyz` identify
process health. All routed document responses are no-store, deny framing (except `/embed/weather/`,
which only `https://vallery.net` may frame; see [embed](embed.md)), and use a fresh script nonce
with no unsafe-inline/eval. The nonce is generated by Express and overwrites the incoming internal
nonce header before React Router sees it. Root hydration keeps the original document nonce through
client navigation. One trusted ingress proxy hop is configured, and forwarded authority is normalized
to the allowlisted public host. Logs contain only fixed route templates, status and latency.

Current data is seeded by the loader into a request-local QueryClient. Polls use one shared identity,
15-second spacing, a 120-second backoff ceiling, no focus/reconnect retry, and cancel when hidden.
The API-unavailable label retains old observation times and continues aging values. A successful
response containing unavailable/null measurements instead invalidates the earlier cached numbers;
it does not claim a transport failure. An API `cached` state describes API fallback, without guessing
whether the physical station feed failed. The shared `useCurrent(initial, apiUnavailable, options)`
hook additionally supports `refreshOnResume: true` and `jitterFraction` (clamped to 0–0.2) for the
separate embed surface; Today keeps its existing next-tick resume and exact 15-second base interval.
Repeated visibility events do not create overlapping refreshes.

Display units are URL state; source values stay canonical. Registry discovery supplies required
rational affine conversion recipes and labels. If discovery is unavailable or mismatched, the UI
shows canonical source units with an explicit conversion-unavailable notice. It never substitutes
an independently guessed conversion. Missing is a reasoned null, never a fabricated zero. Windowed
rain is labelled derived and is excluded from the direct-observation selector.

History identifies raw `resolution_seconds: 0` as unbinned source observations, not a physical
sampling cadence of zero seconds. Positive-resolution aggregate payloads cannot enter that view.
Bounded API input errors retain only a whitelisted code and numeric resolution suggestion; messages
and request identifiers never enter hydration. A rejected raw query never silently selects an
aggregate or another statistic. History shows the source interval, reported gaps and support metadata. uPlot receives
nulls at missing intervals and has a complete SSR table alternative. Exports are bounded JSON pages;
following a cursor or choosing another interval exposes older retained data. The archive calendar
selects solar-cycle dates; its separate bounded catalog clearly labels its filter/pagination scope.
Day pages retain three cameras by two segments, with honest uncommissioned metadata states.

Day, video and Today pages parse `/api/v1/timelapses` leniently through the generated types: an
asset whose URL is not a same-origin `/media/<uuid>` is dropped, an unknown state degrades to
`unavailable` and one malformed entry is dropped rather than the page. Published and
partial-coverage products with the full media set receive a native player; a partial product shows
a visible coverage label (slot coverage from the sidecar). Unavailable or withdrawn products keep
their text and source interval but expose no player or poster. The player never autoplays; quality
changes retain the playhead and pause other players. Native downloads and the JSON sidecar stay on
the same origin. Today shows, per camera and segment, the newest catalog entry's state, poster link
and keogram, or "pending" when nothing has been published. The day page reads
`/api/v1/keograms?cycle_date=` (#37) and shows each published keogram's thumbnail with a bin
slider (arrow keys step one of the 1,440 bins; the readout gives the bin's UTC interval, ±half a
bin, and whether it has a capture) and a link that opens the recording at the bin's midpoint
(`?t=`); clicking the image does the same. Pending, unavailable and failed keograms say so.

### Design system and navigation (2026-10-27 redesign)

The site uses vallery.net's tokens and components. `web/app/styles.css` holds all of them: IBM Plex
Sans and Mono, ink, forest and mint, the sticky header with the V wordmark, cards, tags and chips. The
rationale is in [the redesign record](../decisions/2026-10-27-frontend-redesign.md).

- **Sections.** The sections are Now, Timelapses, History, Almanac, Events and Search
  (`components/site-header.tsx`). Timelapses owns `/archive/`, `/day/`, `/timelapses/` and `/stills/`.
- **Units.** The °F/°C toggle is a pair of plain links that rewrite only `units`, so it works without
  JavaScript. Section links carry `units=metric` forward.
- **Reason codes.** `humanize()` in `lib/format.ts` renders a snake_case code as words. Any other text
  shows exactly as received.
- **Styling.** Never add inline `style` attributes, because CSP forbids them and the e2e suite checks.
  Add a class to `styles.css` instead.
- **Accessibility.** Keep targets at least 24 px, and 44 px for primary controls. axe WCAG 2.2 AA runs at
  320, 768 and 1440 px.

### Linked playback (#40)

One route-local controller (`components/linked-playback.tsx`) owns the media revision's sidecar
time map and the source-UTC cursor. The browser fetches the sidecar (`/media/<id>`) and three
aggregate requests whose `start`/`end` are exactly the segment's `[a, b)` (mean temperature,
humidity, pressure and wind; maximum gust; rain total), at the finest epoch-aligned resolution
that keeps ≤300 intervals per series (5 min for a 12–24 h segment), so well under the API's
5,000-point ceiling on every device. Nothing is fetched per frame.

Mapping (`lib/time-map.ts`) is exact integer-microsecond arithmetic: frame k owns
`[a + k(b − a)/N, a + (k + 1)(b − a)/N)`; player time t shows frame `floor(60t)`; a seek goes to the
middle of the target frame's display window. A sidecar whose interval, frame count, step or tick
total disagrees with the catalog entry is refused, and the page plays without linking. Playback
moves the cursor only when the frame changes, so a seek never echoes back as another seek. Plot,
keogram (1,440 equal UTC bins, D10; once the browser has read the segment's `/api/v1/keograms`
entry, its state, image, exact bin map and gap runs, otherwise the catalog's), event and time-input selections all seek through the same map;
an instant outside `[a, b)` is rejected with a notice, and an event interval is clamped to its
overlap. Slate frames are shaded and labelled at their true length; telemetry gaps are line breaks
and read "no observations". Every explicit seek updates `?t=<UTC>` with `history.replaceState`;
"Link to this moment" carries the cursor. Keyboard: the plot group and keogram are sliders (arrow
keys step one interval or bin; Page Up/Down step 12 intervals or 60 bins; Home/End), and the UTC time input seeks (without
JavaScript it reloads with `?t=`). The plotted values have a text summary and a table.

| Symptom | Check |
|---|---|
| "source-time map is unavailable or does not match" | Fetch the sidecar URL from the catalog entry; compare its `source_interval`, `time_map.frames` and step with `/api/v1/timelapses/<id>`. A mismatch is a publication defect (#15/#18), not a web bug. |
| "Weather history API unavailable" on a video page | The aggregate reads failed; see `weather_api_db_errors_total{operation="aggregates"}`. Playback and seeking still work. |
| "Keogram pending/unavailable/failed" | `/api/v1/keograms?cycle_date=<date>&camera=<camera>&segment=<segment>`; a `failed` reason names the pipeline stage ([pipeline](pipeline.md#keograms)). Playback is unaffected. |

### Search (#27)

`/search/` (`routes/search.tsx`, `lib/search.ts`) is loader-less: SSR renders the form from the URL,
and the browser sends `POST /api/v1/search` (#25) itself, so search never takes an SSR API slot.
The URL is the whole query: `q`, `from`/`to` (America/Denver calendar days, last day inclusive,
sent as the half-open UTC interval between local midnights), repeated `camera` and `segment`,
repeated `p=<metric>.<statistic>:<op>:<value>:<unit>:<min_coverage>` (ops `lt le eq ge gt`; units
`mm in`, `m/s km/h mph`, `degC degF`, always explicit), `top_k` (omitted when 10) and `units`
(always present). D12 ceilings are checked before sending (≤512 Unicode scalars and no control
characters, ≤8 filters over ≤31 days of UTC duration, `top_k` 1–20); any invalid parameter is
listed and nothing is sent, and the form keeps the raw value for correction.

One request per submitted URL or "Search again": none while typing, no automatic retry, no
prefetch, `cache: no-store`, no cookies, a 10 s client deadline. A newer search aborts the older
request and a late older response is ignored. States: hybrid, lexical with its reason
(`embedding_unavailable` and `embedding_busy` show the AI-offline/busy banner; `lexical_no_terms`
explains the text cannot match), numeric, empty, busy (429 with its `Retry-After`), rejected (400)
and unavailable (503, network, malformed). Hits from one video collapse into one card. A window's
seek links to `/timelapses/<camera>/<cycle date>/<segment>/?t=<UTC>` only when its source instant
lies in the cited interval inside the recording's interval (exact microseconds, `lib/time-map.ts`)
and its media offset is within a segment's 120 s timeline; otherwise "Location unavailable".
The cycle date is the local date the recording starts. Measured matches are labelled whole-video;
rain below 95% coverage is "Unknown" when zero and "At least" otherwise, never "0 in".
Display conversions come from `/api/v1/weather/metrics`, fetched only when a result has
measurements.

| Symptom | Check |
|---|---|
| Every search says "Search unavailable" | `curl -s -X POST https://weather.vallery.net/api/v1/search -H 'content-type: application/json' -d '{"start":"2026-07-01T06:00:00Z","end":"2026-07-08T06:00:00Z","query":""}' -o /dev/null -w '%{http_code}'` from outside; anything but 200 is the API or its route, see [search](search.md) (live wiring is #50). 200 with this banner means the browser's request failed: check the browser console for a CSP or network error. |
| Persistent "Search is busy" | The API's admission or Traefik limits; see [search](search.md) failure modes. |

Fonts are the exact approved Fontsource 5.3.0 IBM Plex Sans Variable and Mono members. Their original
OFL notices are served at `/fonts/OFL-sans.txt` and `/fonts/OFL-mono.txt`.
`python scripts/check_web_assets.py` verifies all four hashes against `font-provenance.json`.
The fixture source contains synthetic timestamps/measurements only and is never imported by a live
route. Tests and fixture API code are excluded from the runtime image.

Lightweight verification: `pnpm --dir web typecheck`, `pnpm --dir web lint`, and `pnpm --dir web test`.
Builds, Playwright and synthetic media generation run only through approved
in-cluster fleet CI. The shared Weather CI tooling image bakes PostgreSQL, exact Playwright 1.64.1
browsers and system libraries, and qualified FFmpeg 9.0.2; `bootstrap-browser.sh` only verifies the
readable `/opt/ms-playwright` closure and generates synthetic fixtures as UID1001. It never runs apt
or installs system libraries at validation runtime. The browser check also scans every compiled client
asset, including lazy routes, for private endpoints/configuration, fixture identifiers and source maps
without printing asset contents. WX-20 is not complete until the three-engine responsive/axe/JS-off/chunk-reload checks
and live pinned web image have passed. Source tests alone do not establish those outcomes.

Metrics `weather_web_api_requests_total{route,result}`, `weather_web_api_inflight` and
`weather_web_ssr_inflight` distinguish API transport/shape/body-budget/admission failures from an HTTP
200 degraded page. `weather_web_ssr_failures_total{reason}` records overload, absolute deadline
termination and uncaught render failures, including connections closed before an HTTP finish event. Labels are fixed route templates and a bounded result vocabulary; no query,
station identity or upstream address is logged. `weather_web_request_duration_seconds` covers HTTP
status and asset 404s. Monitoring-stack owns scraping and alert/probe policy.

The web Dockerfile pins the commissioned predecessor and retains its hashed assets. A build emits
`.weather-assets.json` with only that build's own path, size and SHA-256 identities before copying
one predecessor. Subsequent builds read that inventory, verify every predecessor byte and reject
filename collisions with different content. The closure is limited to 512 files / 64 MiB total and
8 MiB per file; older ancestors do not accumulate. Repin `previous` to the live web digest in the same change as each web promotion (#21:
the pin had stayed on the scaffold image, so a held tab's chunks 404ed after rollouts).
A held tab that requests a chunk the new build no longer has reloads exactly once
(`app/lib/chunk-reload.ts`, guarded by a `sessionStorage` timestamp); a second failure within 60 seconds
surfaces instead of looping, and a tab still open at a later promotion gets one fresh recovery.
The e2e fixture ingress mirrors `deploy/k8s/ingress.yaml` routing: `/api/` to api, everything else to
web. `/media/` and `/downloads/` are added there only when #20 routes them in production.

`ci.sh browser` runs the single-worker fixture matrix in all three engines, then
`scripts/web-browser-report.mjs` writes the compact `/workspace/ci-test-report.json` output parameter
(capped at 60 KiB). It requires every configured case to pass without skips or retries and records
checksums for the 27 synthetic Today/history/About screenshots; the full test output, traces and
screenshots stay in `artifacts/` for that run.

Optional polling jitter is sampled once per request cycle, so one-second source-age renders cannot
continually reset the interval. Today retains zero jitter by default.


Strict-CSP qualification uses Zod's interpreted (`jitless`) path before schema construction. Its
normal caught eval-capability probe still emits a CSP violation in browsers, so fallback after the
probe is insufficient. The source regression blocks dynamic Function construction in a separate
Node process and verifies zero probes. The browser matrix checks the untouched hydrated app's CSP
before axe runs. Axe's own WebKit elements-from-point polyfill writes inline pointer-event styles;
that tooling noise is separated after the pre-scan assertion while all WCAG rules and non-style CSP
checks remain enabled. Production CSP is unchanged and allows neither inline scripts nor eval.

Auto quality is chosen once by the browser's own resource selection over `<source>` media queries
(mobile at ≤767 px, else web), identically with or without JavaScript; a viewport change after load
never swaps media, so a phone fetches one rendition. Only a user quality change reloads, and it
retains the current loaded playhead; pending seeks survive additional switches while new metadata is
loading. Framework errors use bounded renderer metrics; the default
React Router URL/stack logger is overridden so only the server's route-template/status/latency log
is emitted. The first real three-engine fixture run and its failed result remain retained for
comparison; a failed run is never treated as acceptance.

Playwright 1.64.1's WebKit 27.2 reports one false `style-src-attr` violation per native
`select` in its user-agent shadow tree (confirmed upstream:
https://github.com/microsoft/playwright/issues/43497 and WebKit 327212). Qualification
keeps the production CSP intact, requires no inline style attributes in the serialized SSR document, and compares
pre-axe violations to the exact native-select count only in that engine. A minimal empty/native
select control and a real forbidden-inline-style negative control run in every engine; the
negative control must add a violation. Other directives and all Chromium/Firefox violations
must be empty. A browser change that fixes the defect fails the control and requires removing
this narrow accounting. The retained failed browser03 run has 78 passes, 15 WebKit control
failures, and 21 checksummed screenshots; it is not acceptance.

History chart labels use two lines (date, then time and UTC offset) with a 150-pixel
minimum tick spacing and reserved axis height. This avoids overlapping full timestamps while
preserving the distinction between the two repeated 01:15 observations. The table retains exact
source timestamps. uPlot sizes its canvas using CSP-permitted JavaScript style properties;
qualification checks serialized HTML for inline style attributes, rather than forbidding those
legitimate computed dimensions.

## Edge rate limits (#148)

The site Middleware `weather-rate-limit` allows `average: 30, burst: 60` per visitor
(`Cf-Connecting-Ip`), and search allows 30/min, burst 10. Traefik keeps these buckets per pod, and
`traefik-apps` runs one pod on each of the 5 workers. A visitor's effective limit therefore
depends on how many of cloudflared's pooled origin connections reach different pods: 1× when
they concentrate on one pod, up to about 5× when they spread.

Measured on 2026-10-26 with one client hitting `/api/healthz`: at 20:5xZ, bursts of 150–400
requests at 5–200 parallel got 67–81 × 200, which is one bucket (60 + 30/s × t). That morning
an 800-request burst at 200 parallel got 666 × 200 in 3.3 s, which is about 5 buckets.

Jason's decision (2026-10-26): keep the per-pod values and accept the bounded ≤5×. Dividing by
5 would make the limit 5× too strict whenever traffic concentrates. The api pods' own caps (32
media streams per pod, the search slot) bound the expensive paths. A shared Redis-backed limiter
in `traefik-apps` (network-infra) is the exact option if abuse appears.
`/assets/*` carries no rate limit: 300 requests at 100 parallel all returned 200.

Probe a burst from one client:
`seq 1 150 | xargs -P 30 -I{} curl -s -o /dev/null -w '%{http_code}\n' https://weather.vallery.net/api/healthz | sort | uniq -c`
