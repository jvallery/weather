# Tempest receive and drain

The `tempest-receiver` role is prepared by #12. #9 gates its database migration and integration acceptance; #5 commissions the Linux workload. This source change does not enable a receiver or access the real hub. The approved CI database is isolated, socket-only PostgreSQL 16.15 with pgvector 0.8.6, using the existing schema CI lifecycle. Kill/outage tests must never run on the Mac.

Run `weather tempest-receiver`. Project a public `receiver.json` and Secret `weather-tempest` into `/etc/weather/telemetry` (override directory with `TELEMETRY_CONFIG_DIRECTORY`). The public file requires `interface_name`; optional fields are `hub_source_port`, `spool_directory`, `capacity_bytes`, `future_seconds`, `metrics_port`. It rejects private identity/address fields and duplicate keys. The exact three Secret filenames are `TEMPEST_HUB_SOURCE` (IPv4 text), `TEMPEST_HUB_SERIAL` (one serial), and `TEMPEST_DEVICE_SERIALS` (a JSON array of 1–32 distinct serial strings). Atoms are bounded printable ASCII without whitespace; values retain their exact case and are never inferred, trimmed, defaulted or accepted from argv. `--help` opens no listener. Errors and object representations omit private values.

The default spool path is `/var/lib/weather/telemetry`, capacity 1 GiB, future tolerance 120 seconds and metrics port 9000. Commissioning supplies the real private values through existing Secret custody, never public Git. Interface index is resolved inside the pod; no DNS lookup, send, root, raw socket or capability is required. Missing custody—including the currently unproved hub source—fails startup rather than falling back to an old reservation or accepting every sender.

Use the schema's mounted database credential/CA directory and `weather_ingest` role. It has SELECT/INSERT on custody, provenance and incident tables, with no general UPDATE/DELETE. Two fixed SECURITY DEFINER functions can mark disputed fields ineligible or repeated strike multiplicity ambiguous. No normalized values can be overwritten by those functions. The database retains all received raw and normalized history indefinitely; there is no TTL/delete job.

`/metrics`, `/live`, `/ready` run independently of the receive/drain loops. Readiness means the receive thread is alive and the durable spool is below critical pressure; DB outage is exposed separately through drain errors and backlog age. No family-age sample exists before that family is actually received in the current process. Replay never freshens it. Termination stops new reception, lets the bounded transaction finish and closes SQLite; use at least 40 seconds termination grace when commissioning.

Expected signals: received/spooled/committed/projected counters, reasoned rejection/truncation counters, quarantine/capacity/overflow/uncertain-write counters, original family packet age, spool rows/logical/physical bytes and capacity, oldest pending receipt drain lag, drain/ack errors and unknown-loss gauge. `projected` counts committed canonical rows; a private receipt-row provenance record also exists for quarantined siblings. No serial, endpoint or raw packet is a metric label or log field.

During a database outage, leave the receiver/spool running. When access returns, the bounded drain retries the same IDs. Local acknowledgement only follows known database commit success. Check authoritative CNPG row counts and original timestamps as well as an empty spool before claiming recovery. An uncertain commit is not a reason to mint replacement IDs or wipe the spool.

At 70% logical data usage investigate; at 85% mark collection degraded. The physical limit includes retained corrupt generations and sidecars. At the limit new arrivals are dropped with exact `capacity_loss` when diagnostic storage is healthy; existing pending bytes are preserved. Diagnostic write failure or restart creates unknown loss, never a fabricated zero. In `telemetry_loss_snapshot`, counts are cumulative per generation/reason: take the latest/max, do not sum snapshots.

An unreadable active generation is renamed under `quarantine/<opaque-id>` intact. Retain it and its marker for offline recovery. Do not delete, edit, vacuum, copy over or force-open a live writer's database to clear a health check. A local owner lock prevents concurrent use. If PVC/node custody is uncertain, preserve it and resolve through the storage owner; mounting another writer or deleting retained data is not a recovery step.

`weather.receipt_row_provenance` links each receipt/row/parser to canonical observations or a fixed quarantine reason. `receipt_integrity_incident` preserves alternate bytes under a reused UUID. `observation_conflict` links conflicting receipts and disputed official fields. Exact raw is authoritative; JSONB-incompatible values or values outside the bounded numeric storage policy have SQL-NULL parsed envelopes and explicit tagged private evidence. Inspect through authorized private access without printing packets or endpoints into tickets/logs.

`weather.telemetry_coverage_minute` exposes private per-family receipt counts and reported cadence. `telemetry_coverage_interval` carries clipped/reconstructable bounds and reason. A 90-second expected-arrival gap, reduced cadence, DB backlog and source clock behavior are separate facts. These diagnostics never become rain/temperature support coverage. The conflict outbox topic is `telemetry.conflict`, payload `{incident_id,family,observation_id,source_ts,fields}`; #14 owns source-matched current invalidation and safe public projection.

Validation before acceptance: focused pure tests; cluster `scripts/ci.sh integration` against migration 0002; T01–T09/T16–T18/T20 evidence including both abrupt exit points, missing DB transport, exact capacity drops and unchanged source time; CI privacy/log scan; all enforced checks. Live UDP/NAD/storage/firmware checks occur in #5, with private evidence and bounded resources.

Device envelopes missing `hub_sn` from a matching configured source/device are retained raw-only as `missing_hub_identity`; they are not declared protocol-invalid. v171 examples do not establish a normative required-field schema. Commissioning must explicitly qualify compatibility before relaxing this normalization boundary. A present wrong identity is dropped.
